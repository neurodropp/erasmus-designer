# Reconciling source IDs after an LWC import

The semantic archive `compress`/`decompress` can recreate numeric source IDs. The number alone therefore does not identify the content at the destination. The engine maintains an immutable reference in `index/lwc-source-identities.json`: for each local ID, `original_lwc_id`, `content_hash`, `bytes`, `title` and `origin`, with `schema_version: lwc-source-identities-v1` and provenance for the official detection. This reference must be included and verified in the bundle manifest, together with the original map. A hash declared in the JSON without verified provenance and a verified bundle is not an independent authenticity attestation.

`python3 scripts/reconcile_lwc_sources.py` produces a read-only JSON plan. The root is derived from the location of the transferred script; the command does not depend on the current directory. It queries only `scripts/lwc source list --limit 100 --offset N`, reads `sources`, `limit`, `offset`, `has_more` and follows every page. The CLI already returns JSON: a nonexistent `--json` option is not used. The canonical database is not opened or modified directly.

Every content item must have an exact, unique SHA256 hash in both the reference and the destination, with the same number of bytes. All expected sources must be present, and all returned sources must be recognized. Extra or missing sources, duplicate or malformed hashes, different sizes, incomplete pages, repeated numeric IDs and JSON with duplicate keys cause rejection. Matching does not use title, origin or the old numeric ID; the plan separately records whether the title, origin and ID have changed. A different historical origin does not authorize rewriting the field.

The plan contains `matches` with the original ID, destination ID and hash for each source, the candidate map, `numeric_ids_unchanged`, and SHA256 digests of both inputs, the result and the CLI detection. The active map must be the original map, the already verified candidate, or an intermediate map linked to the originals by a verified chain of backups/receipts. `verified_previous_history` lists the files and digests in the chain. Each receipt verifies identity, digest, map and matches; the result must match the active map or the backup from the following step. A partial, unknown or altered map is not repaired blindly. Backups and receipts are included in the export under a strict allowlist to support later migrations.

After verifying the bundle, importing the memory and reading the plan, run the following on the destination only:

```sh
python3 scripts/reconcile_lwc_sources.py
python3 scripts/reconcile_lwc_sources.py --apply
python3 scripts/reconcile_lwc_sources.py
```

`--apply` atomically replaces only the active `index/lwc-source-map.json` file, if needed. Before replacement, it preserves the exact previous bytes in `index/source-reconciliation/source-map.<SHA256>.json` and a JSON receipt in the same path. Existing backups and receipts must be identical to the expected data; they are not overwritten in case of conflict. The receipt records the prepared intent and the expected inputs and output: completion is evidenced by equality between the active map hash and `after_map_sha256`. This distinction is explicit because the map, backup and receipt do not form a three-file atomic transaction. If the process is interrupted, a prepared receipt by itself does not prove that the change was applied. The command returns `applied: true` only after successful replacement. A second run with the map already correct writes no new files.

The tool rejects symlinks in the root and in paths it uses; backup and receipt names are derived from hashes, with no paths originating from sources. It rechecks the reference and map before replacement and preserves any concurrent changes it detects. Nevertheless, run it with other map producers stopped: this is not a synchronization protocol against concurrent writers or an adversarial process that changes the filesystem during execution.

The released original map remains immutable in the verified bundle and in the exact backup. The update applies only to the operational map of the new destination: it does not rewrite historical source IDs in packages, archived/accepted receipts, textual citations, `raw/`, revisions in `sources/`, `origin` fields or `.lwc/`. Old attestations remain evidence of the old environment. To compare structured citations before and after import, link them through `content_hash` and the ID pair reported in the plan, without modifying historical receipts.

Reconciliation does not attest to page content, the integrity of all citations, preservation of the complete history, eligibility, online freshness or the validity of gates at the destination. Separate import, `doctor`, `lint`, retrieval and citation comparison checks are required. The alternative is the complete canonical backup, separately verified, when the identifiers and history of the original database must also be preserved. The plan has the advantage of making the active map of a semantic import auditable; its limitation is its dependence on the verified immutable reference and CLI metadata.

Regressions in `tests/test_reconcile_lwc_sources.py` use temporary destinations and a simulated CLI. They cover remapping by hash, a plan with no writes, backup and receipt, idempotency, missing/unknown/duplicate sources, byte mismatch and invalid hashes, a hostile old map, symlinks, pagination, CLI errors, evidence conflicts and detected concurrent modification. They do not replace testing a real new import.
