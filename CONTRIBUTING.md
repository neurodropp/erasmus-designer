# Contributing

Contributions must preserve the separation between the reusable engine, normative evidence, and private candidate work.

1. Create a branch from the current protected default branch.
2. Use only public authoritative sources or synthetic fixtures.
3. Keep IDs, source scope, call year, action, sector, and provenance explicit.
4. Update tests and operational documentation with behavioural changes.
5. Run the repository preflight and relevant unit tests.
6. Request review before merging changes to routing, gates, privacy rules, source promotion, or form handling.

Do not commit real applications or assessments, even when names have been removed: combinations of project code, title, partners, dates, or narrative can still re-identify a case.
